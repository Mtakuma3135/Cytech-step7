## 実施内容

### 1. 注文ステータスをpending起点に変更
- `Order::STATUS_PENDING / STATUS_PAID / STATUS_CANCELLED` を追加
- 注文作成時は`pending`で作成し、`app/Services/PaymentService.php`(現状は即時承認するだけのモック)による決済確定処理を経て`markAsPaid()`する構造に分離
- 実際の決済ゲートウェイを導入する際は`PaymentService::charge()`をWebhook経由の非同期処理に差し替えられる設計
- 注文一覧・詳細・完了画面に`<x-order-status-badge>`コンポーネントを追加し、pending/paid/cancelledをそれぞれ表示

### 2. カートをDB永続化に変更
- `cart_items`テーブルを新設(`user_id`または`session_id`のどちらかで所有者を識別)
- `CartService`をセッション配列からDBクエリベースに書き換え
- ログイン時、ゲスト時に使っていたカートをユーザーのカートへ統合する`mergeGuestCartIntoUser()`を追加

### 3. 管理者ロールを追加
- `users.is_admin`カラムを追加(ユーザー自身の入力で書き換えられないよう`$fillable`には含めていない。付与はSeeder/tinker等の管理操作のみ)
- ログイン後の遷移先を管理者は`/products`、一般顧客はショップトップ(`/`)へ分岐
- `EnsureUserIsAdmin`ミドルウェアを追加し、`/products`・`/admin/companies`配下を管理者のみアクセス可能に(非管理者は403)
- ナビゲーションも管理者ログイン時のみ「商品管理」「メーカー管理」リンクを表示するよう変更

### 4. 旧購入API・salesテーブルを削除
- `SalesController`・`Sale`モデル・`routes/web.php`と`routes/api.php`の`/purchase`ルートを削除
- `sales`テーブルをDropするマイグレーションを追加(Down時は元のスキーマを復元可能)
- `Product::sales()`リレーションも削除

## 作業中に発見・修正した既存の不具合

### routes/auth.php の重複クロージャ問題（重要）
管理者ロール対応の動作確認中、「ログイン後の遷移先が常に`/products`になる」という再現性の高いバグに遭遇。原因調査の結果、`routes/auth.php`に`AuthenticatedSessionController::store()` / `RegisteredUserController::store()`を**完全に迂回する独自クロージャ**が以前から残っており、`POST /login`・`POST /register`が実際にはコントローラーではなくこの古いクロージャで処理されていたことが判明（`php artisan route:list`で action が `Closure` になっていることで発覚）。ログインクロージャは常に`route('products.index')`へ固定でリダイレクトしており、今回追加したロール別分岐が一切反映されない状態だった。

標準のBreeze方式（コントローラー呼び出し）に統一し、迂回されて完全にデッドコード化していた`app/Http/Requests/LoginRequest.php`・`RegisterRequest.php`（`AuthenticatedSessionController`が実際に使う`Auth\LoginRequest`とは別の紛らわしい同名クラス）も削除した。

### SessionGuard のセッションID再生成タイミング
カートマージ機能の実装時、`Illuminate\Auth\Events\Login`イベントのリスナーで`session()->getId()`を読んでも、`SessionGuard::login()`が**Loginイベント発火前にセッションIDを再生成済み**のため、ゲスト時のセッションIDと一致せずマージが機能しないことが判明。イベントリスナー方式をやめ、`AuthenticatedSessionController::store()`内で`Auth::attempt()`を呼ぶ**前**にセッションIDを変数へ退避し、それを明示的に`mergeGuestCartIntoUser()`へ渡す方式に変更して解決。

### UserFactory の name カラム参照
`php artisan test`を実行したところ24件中19件が失敗。原因は`database/factories/UserFactory.php`が、以前のマイグレーションで削除済みの`users.name`カラムを参照し続けていたため。`name`の生成行を削除して修正（このバグは今回のスコープと無関係、以前から存在）。
